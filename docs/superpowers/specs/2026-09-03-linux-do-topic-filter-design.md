# LINUX DO 帖子过滤器设计

## 1. 目标

新增一支油猴脚本，为 `https://linux.do` 的帖子列表提供标题、标签和类别过滤。用户可分别配置三类规则；任一规则命中的帖子不在列表中展示，并可在保存前预览当前页面将被过滤的帖子。

脚本只改变当前浏览器中的页面显示，不修改帖子、账号或站点数据。

## 2. 范围

当前版本包含：

- 标题关键字、标签名称及类别名称过滤；
- 过滤词的本地持久化；
- 输入过滤词时的实时预览；
- Discourse 单页路由切换及无限滚动新增帖子的自动过滤；
- 清空设置后恢复全部帖子。

当前版本不包含：

- 作者、正文或帖子摘要匹配；
- 正则表达式、通配符、排除规则或多组规则；
- 跨浏览器同步、云端配置或过滤统计；
- 主动翻页以预览尚未加载的帖子；
- 网络响应改写或 Discourse 内部插件 API 集成。

## 3. 页面契约与技术选择

LINUX DO 使用 Discourse。帖子列表接口的路径会随列表变化，例如：

```text
https://linux.do/tag/none/l/latest.json
https://linux.do/tag/444/l/latest.json
```

接口响应中的 `topic_list.topics[].title`、`tags` 与 `category_id` 可辅助过滤，`more_topics_url` 表示后续分页。然而响应不含类别名称映射，而页面 DOM 已含三类文本，故脚本不读取或拦截这些接口，避免增加路由、分页和登录态处理。

脚本使用 Discourse 列表的公共 DOM 结构：

```text
帖子行  .topic-list-item[data-topic-id]
标题    .title.raw-topic-link[data-topic-id]
标签    .discourse-tag
类别    .badge-category__name
```

脚本匹配 `https://linux.do/*`，不依赖标签 slug、标签 ID 或某一种列表路径。非列表页面找不到帖子行时不执行过滤。

## 4. 匹配规则

1. 标题、标签和类别各有一个配置框，每行一个规则。
2. 保存或预览前去除每行首尾空白，并忽略空行。
3. 重复过滤词按不区分大小写去重，保留第一次出现的写法。
4. 标题和标题过滤词使用 JavaScript `toLowerCase()` 后作子串匹配。
5. 标签、类别及相应规则使用 `toLowerCase()` 后作完整名称匹配。
6. 标题、标签或类别任一规则命中，帖子即被过滤。
7. 三组规则皆为空时不隐藏任何帖子。
8. 标题元素缺失或标题为空时，该帖子保持可见。

不作 Unicode 近似匹配、繁简转换或分词；这些行为只有出现实际需求时再增加。

## 5. 配置与预览交互

油猴菜单提供“设置帖子过滤词”命令。执行后打开脚本创建的原生 `<dialog>`：

- 三个文本框分别载入标题过滤词、标签名称和类别名称，每行一个；
- 输入时实时显示“当前页面将过滤 N 个帖子”；
- 预览区列出命中的帖子标题及来源，例如“标题：抽奖；标签：人工智能；类别：搞七捻三”；
- 标题为普通链接，点击后在新标签页打开，并使用 `rel="noopener noreferrer"`；
- “保存并应用”清理并保存过滤词，关闭对话框后立即重扫当前列表；
- “取消”或按 Escape 关闭对话框，不修改已保存配置和当前过滤结果。

预览使用文本框中的草稿，页面本身仍使用已保存配置，直至用户保存。预览查询全部当前 DOM 帖子行，包括已被脚本隐藏的行，因此重新打开设置时仍可看到现有过滤结果。

预览仅代表当前已经加载的帖子。对话框打开期间若页面新增帖子，预览随列表更新；尚未滚动加载的分页不会被主动请求。

标题、标签、类别及过滤词仅通过 DOM 的 `textContent` 创建预览内容，不拼接为 HTML。

## 6. 状态与页面处理

脚本使用以下油猴能力：

```text
GM_registerMenuCommand
GM_getValue
GM_setValue
```

三组规则均以清理后的一行一个字符串存于脚本本地存储。标题沿用 `keywords`，标签和类别分别使用 `tagKeywords` 与 `categoryKeywords`，故已有标题配置可直接保留。启动时读取一次，配置保存后更新内存状态。若某个存储值不是字符串，则该组按空配置处理。

页面处理流程如下：

1. `document-start` 时注入唯一命名的隐藏样式；
2. DOM 可用后扫描已有帖子行；
3. 对每行读取标题、标签和类别，根据当前规则添加或移除脚本专用隐藏 class；
4. `MutationObserver` 监听子树中新加入的节点，只收集该节点自身、祖先或后代中的帖子行并重新判断；
5. 配置保存或清空时，全量重扫当前帖子行；
6. 预览打开时，相关列表变化同时刷新预览。

隐藏帖子采用 CSS `display: none !important`。脚本不删除帖子节点，故可在配置改变后恢复，也能纳入预览。

监听器只观察 `childList` 和 `subtree`，不观察 class 属性，避免脚本自身切换隐藏 class 引发循环。

## 7. 失败行为

- 读取到异常存储值时不应用过滤；
- 保存失败时保持对话框打开并显示错误，既有配置继续生效；
- 找不到列表项或标题元素时保持原页面内容可见；标签或类别元素缺失时只跳过相应规则；
- 单个帖子处理失败时不移除该帖子；
- 网站更改 DOM 结构时最坏结果是过滤失效，不应影响浏览、导航或登录；
- 脚本不发网络请求，不读取 Cookie、localStorage 或其他登录信息。

## 8. 实现范围

实现阶段拟改动：

```text
scripts/linux-do-topic-filter.user.js
tests/linux-do-topic-filter.test.js
docs/linux-do-topic-filter.md
README.md
```

不增加依赖、包管理器、构建工具、设置框架或网络权限。标题过滤首版版本号为 `0.1.0`，加入标签与类别过滤后升为 `0.2.0`。脚本使用仓库现有 Raw GitHub 地址作为 `@updateURL` 与 `@downloadURL`。

## 9. 验证

Node 原生测试覆盖：

- 过滤词的清理、空行忽略及大小写去重；
- 不区分大小写的标题子串匹配；
- 不区分大小写的标签与类别完整名称匹配；
- 三类规则独立配置，任一规则命中即隐藏，清空配置后恢复；
- 新增帖子节点受同一规则处理；
- 预览使用草稿配置，取消不修改已保存配置；
- 异常存储值和无标题帖子保持可见。

Chrome 人工验收覆盖：

1. 保存规则后，当前命中标题、标签或类别的帖子立即消失；
2. 刷新页面后设置仍有效；
3. 切换首页、类别页和标签页后过滤继续生效；
4. 无限滚动新增帖子会自动过滤；
5. 预览数量、标题及标题/标签/类别命中来源与实际过滤结果一致；
6. 取消编辑不改变现状；
7. 清空并保存后全部帖子恢复；
8. 非列表页面及站点原有交互不受影响。
