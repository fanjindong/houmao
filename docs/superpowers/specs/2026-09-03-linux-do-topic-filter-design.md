# LINUX DO 帖子过滤器设计

## 1. 目标

新增一支油猴脚本，为 `https://linux.do` 的帖子列表提供标题、标签和类别过滤。用户可分别配置三类规则；任一规则命中的帖子不在列表中展示，并可在保存前预览当前页面将被过滤的帖子。

脚本只改变当前浏览器中的页面显示，不修改帖子、账号或站点数据。

## 2. 范围

当前版本包含：

- 标题关键字、标签名称及类别名称过滤；
- 过滤词的本地持久化；
- 输入过滤词时的实时预览；
- 首屏、Discourse 单页路由切换及无限滚动数据在渲染前自动过滤；
- 清空设置后，后续加载的数据不再过滤。

当前版本不包含：

- 作者、正文或帖子摘要匹配；
- 正则表达式、通配符、排除规则或多组规则；
- 跨浏览器同步、云端配置或过滤统计；
- 主动翻页以预览尚未加载的帖子；
- 主动刷新当前页面以应用刚保存的配置。

## 3. 页面契约与技术选择

LINUX DO 使用 Discourse。帖子列表接口的路径会随列表变化，例如：

```text
https://linux.do/tag/none/l/latest.json
https://linux.do/tag/444/l/latest.json
```

接口响应中的 `topic_list.topics[].title`、`tags` 与 `category_id` 用于过滤，`more_topics_url` 表示后续分页。类别名称及父子关系取自 Discourse 首屏预载的站点类别数据。

首屏帖子来自：

```text
#data-preloaded
```

后续页面切换和无限滚动由站点自身的 XHR 取得。脚本不依赖具体列表路径，只处理含有 `topic_list.topics` 的 JSON；其他响应原样保留。两处皆在 Discourse 创建帖子模型和 DOM 前完成过滤。

## 4. 匹配规则

1. 标题、标签和类别各有一个配置框，每行一个规则。
2. 保存或预览前去除每行首尾空白，并忽略空行。
3. 重复过滤词按不区分大小写去重，保留第一次出现的写法。
4. 标题和标题过滤词使用 JavaScript `toLowerCase()` 后作子串匹配。
5. 标签及相应规则使用 `toLowerCase()` 后作完整名称匹配；类别同时匹配完整名称和以“父类别,”开头的子类别路径。
6. 标题、标签或类别任一规则命中，帖子即被过滤。
7. 三组规则皆为空时不剔除任何帖子。
8. 标题字段缺失或标题为空时，该帖子保持可见。

不作 Unicode 近似匹配、繁简转换或分词；这些行为只有出现实际需求时再增加。

## 5. 配置与预览交互

油猴菜单提供“设置帖子过滤词”命令。执行后打开脚本创建的原生 `<dialog>`：

- 三个文本框分别载入标题过滤词、类别名称和标签名称，每行一个；
- 输入时实时显示“当前已加载数据将过滤 N 个帖子”；
- 预览区列出命中的帖子标题及来源，例如“标题：抽奖；标签：人工智能；类别：搞七捻三”；
- 标题为普通链接，点击后在新标签页打开，并使用 `rel="noopener noreferrer"`；
- “保存”清理并保存过滤词，但不刷新或重排当前列表；
- “取消”或按 Escape 关闭对话框，不修改已保存配置和当前过滤结果。

预览使用文本框中的草稿，页面本身仍使用已保存配置，直至用户保存。脚本在过滤前缓存当前页面已经取得的原始帖子数据，因此预览也包含未交给页面渲染的命中帖子。

预览仅代表当前已经取得的帖子数据。对话框打开期间若页面取得新一批帖子，预览随之更新；尚未滚动加载的分页不会被主动请求。保存后的新规则只作用于随后取得的数据；当前已展示或已剔除的帖子保持不变，直至页面切换或用户手动刷新。

标题、标签、类别及过滤词通过 DOM 属性创建预览内容，不拼接为 HTML。

## 6. 状态与页面处理

脚本使用以下油猴能力：

```text
GM_registerMenuCommand
GM_getValue
GM_setValue
unsafeWindow
```

三组规则均以清理后的一行一个字符串存于脚本本地存储。标题沿用 `keywords`，标签和类别分别使用 `tagKeywords` 与 `categoryKeywords`，故已有配置可直接保留。启动时读取一次，配置保存后更新内存状态。若某个存储值不是字符串，则该组按空配置处理。

页面处理流程如下：

1. `document-start` 时改写页面环境的 `XMLHttpRequest.prototype.open`，只在完成事件中检查 JSON 结构；
2. 以短生命周期 `MutationObserver` 等待 `#data-preloaded` 出现，处理后立即断开；
3. 先汇集站点类别数据，再对 `topic_list.topics` 逐项匹配；
4. 在剔除命中帖子前，将原始帖子按 ID 缓存给当前页面的预览；
5. 只替换 `topics` 数组，`more_topics_url`、用户数据及其他响应字段保持不变；
6. 保存配置只更新本地存储与内存规则，不调用刷新，也不扫描或修改帖子 DOM。

脚本不再观察帖子 DOM，不使用待判定状态、延时器、隐藏 class 或占位样式。帖子若已交给页面展示，此后保持稳定。

## 7. 失败行为

- 读取到异常存储值时不应用过滤；
- 保存失败时保持对话框打开并显示错误，既有配置继续生效；
- 响应不是 JSON 或不含 `topic_list.topics` 时保持原样；
- 找不到标题字段时保留帖子；标签或类别数据缺失时只跳过相应规则；
- 首屏预载或 XHR 改写失败时保持站点原数据，避免阻断浏览、导航或登录；
- 脚本不发起额外网络请求，不读取 Cookie、localStorage 或其他登录信息。

## 8. 实现范围

实现阶段拟改动：

```text
scripts/linux-do-topic-filter.user.js
tests/linux-do-topic-filter.test.js
docs/linux-do-topic-filter.md
README.md
```

不增加依赖、包管理器、构建工具、设置框架或额外网络请求。接口过滤版本升为 `0.3.0`。脚本使用仓库现有 Raw GitHub 地址作为 `@updateURL` 与 `@downloadURL`。

## 9. 验证

Node 原生测试覆盖：

- 过滤词的清理、空行忽略及大小写去重；
- 不区分大小写的标题子串匹配；
- 不区分大小写的标签完整名称匹配，以及类别完整名称与父类别匹配；
- 三类规则独立配置，任一规则命中即从接口帖子数组剔除；
- 父类别规则覆盖子类别 ID；
- 首屏预载及后续 XHR 使用同一过滤规则；
- 分页 URL 及无关响应字段保持不变；
- 预览使用草稿配置，取消不修改已保存配置；
- 保存不刷新或重扫当前列表，新规则作用于后续响应；
- 异常存储值、非帖子响应和无标题帖子保持原样。

Chrome 人工验收覆盖：

1. 首次打开时，命中标题、标签或类别的帖子不会闪现；
2. 刷新页面后设置仍有效；
3. 保存设置不刷新且现有列表不跳动；
4. 切换首页、类别页和标签页后过滤继续生效；
5. 无限滚动新增帖子在展示前完成过滤；
6. 预览数量、标题及标题/标签/类别命中来源与接口原始数据一致；
7. 取消编辑不改变现状；
8. 非列表页面及站点原有交互不受影响。
